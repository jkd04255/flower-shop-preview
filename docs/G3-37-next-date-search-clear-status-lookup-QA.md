# 오후의 정원 G3-37 · 다음 픽업 가능일 / 관리자 검색 지우기 / 고객 가상 예약 현황

## 최신 기준 및 변경 사항
- 기준선: G3-36 `main` (`f49734afd2a3fdf3b86382309cd22dbb13badd78`).
- **고객 날짜 탐색:** `다음 픽업 가능일 선택 ↗`은 날짜를 선택한 경우에만 활성화하며, 현재 날짜 **이후**부터 14일 이내 영업일에서 기존 `pickupSlots()`이 제공하는 최초의 유효 날짜를 선택합니다. 날짜가 바뀌면 기존 시간은 지우고 고객이 재선택해야 합니다. 마지막 예약 가능일에서는 경계 메시지만 표시하며 날짜/요청을 임의 변경하지 않습니다.
- **관리자 검색:** `가상 예약번호 검색`에 글자가 있으면 `검색 지우기 ↗` 버튼을 표시합니다. 버튼 클릭 시 검색어만 지우고 입력창에 키보드 포커스를 복귀시킵니다. 기존 상태 필터, 정렬, 선택한 요청 및 합성 기록은 유지하며 빈 목록/요약을 갱신합니다.
- **고객 가상 예약 상태 조회(추가 요청):** 홈 매장 안내에 전화번호 **뒷자리 4자리** 시연 조회 폼을 추가합니다. `1001`~`1004`는 공개 샘플 ID `DEMO-001`~`DEMO-004`의 **실제 전화번호가 아닌 가상 코드**입니다. 새로운 합성 요청을 고객이 최종 확인하면 그때 입력한 **예시 전화번호 뒷자리만** 해당 가상 ID에 브라우저 탭의 `Map`으로 일시 연결합니다. `localStorage`, URL, 서버, 로그, 합성 예약 레코드에 뒷자리/실제 전화번호를 저장하지 않습니다. 새로고침이나 다른 탭으로 이동하면 이 연결은 사라집니다. 관리자 가상 데이터 초기화 시에도 삭제합니다. 조회 결과는 **가상 예약 ID와 현재 상태만** 표시하며 이름·전체 전화번호·꽃다발·픽업 일시는 표시하지 않습니다.
- 홈과 결과 화면에 '가상 조회'임을 반복 표시하고, 뒷자리 4자리만으로는 **실서비스 본인확인이 불가능**함을 안내합니다. 실서비스 개발 시 실제 예약 기록/인증/개인정보 동의 및 접근 제어는 별도 게이트에서 재설계해야 합니다.
- 기존 디자인·원본 상품 사진·메인 고정 문구 `오늘의 꽃 만나기 ↗`·상품 `상품 상세 보기 ↗`, G3-24~36 UX와 모든 합성 계좌/예약 정책을 보존합니다. 푸터는 `G3-37 STATIC DEMO`입니다.

## QA
- 신규 `tests/g3-37-next-date-search-clear-qa.cjs`는 Chromium + Linux Playwright WebKit 두 엔진에서 (1) 다음 날짜의 유효성 및 시간 초기화, (2) 마지막 가능일/키보드/날짜 직접 수정, (3) 최종 3단계 리뷰·입력값 미저장, (4) 관리자 검색어 지우기/0건/상태·정렬과 교집합/포커스, (5) 샘플 4자리 가상 상태 조회/없는 번호/잘못된 번호/새 합성 요청의 같은 탭 조회, (6) 새 가상 요청 조회 연결이 관리자 초기화에서 소멸, (7) 저장소에 고객 번호/메모/뒷자리 없음, (8) axe WCAG 2.1 A/AA 자동 위반 0, 모바일 320/390px 가로 넘침·JS 오류 0 검사.
- 기존 단일 CI에서 **G3-12~36 전체 Chromium/axe/WebKit 회귀 검사 유지**. 이전 G3-36 푸터 검사는 36 이상을 허용하도록 조정하고 기능 검사는 그대로 보존합니다.
- 전체 QA가 성공한 경우에만 PR squash 병합, `main` 반영, GitHub Pages 배포 성공까지 확인합니다.

## 사용자 확인
1. 가상 꽃다발 예약에서 첫 가능일, '다음 픽업 가능일'을 순서대로 누르고 시간이 자동 선택되지 않는지 확인합니다.
2. 관리자에서 DEMO-001을 검색 후 지우기 버튼으로 전체 가상 요청을 복구합니다.
3. 홈 하단 가상 조회에서 샘플 `1003`을 입력하면 'DEMO-003 · 예약 확정'이 표시되는지 확인합니다.
4. 예시 연락처로 가상 예약을 완료했다면 **같은 탭에서만** 해당 예시 번호 뒷자리로 새 가상 요청의 현재 상태를 조회합니다. 실제 전화번호는 입력하지 마세요.
