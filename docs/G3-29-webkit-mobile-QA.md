# 오후의 정원 G3-29 · WebKit 모바일 예약 흐름 회귀 검사

## 목표와 변경 범위
- 최신 병합 G3-28의 iPhone Instagram 파란 제목 테두리/약한 확대 신고에 대해, Chromium만으로 검증한 한계를 보완합니다.
- **정적 사이트 index.html은 수정하지 않습니다.** 기존 디자인, ‘오늘의 꽃 만나기 ↗’, 카드 ‘상품 상세 보기 ↗’, 3단계 최종 확인, 가상 입금/관리자/캘린더/합성 저장을 모두 그대로 보존합니다.
- 기존 **단일 PR 검사** `.github/workflows/g3-17-browser-qa.yml`에 리눅스 Playwright **WebKit 엔진**을 설치하고, 신규 `tests/g3-29-webkit-mobile-qa.cjs`를 추가합니다. 기존 Chromium/axe 엄격 검사들을 삭제하거나 완화하지 않습니다.
- WebKit 헤드리스 실행은 iOS WebKit 렌더링 엔진 계열을 사용하지만 **iPhone Safari/Instagram의 실제 앱 내 WebView, 키보드 확대 동작을 완전히 재현하지 못합니다.** 실제 기기 확인은 여전히 별도로 필요합니다.

## 자동 검사 범위
1. WebKit 390×844 모바일 터치 상품 상세 → 예약 화면, 비대화형 제목에 불필요한 자동 focus 없음.
2. 예약·검토·결과 제목에만 `outline:none`, 예약 폼 input/select/textarea 16px 이상. 실제 버튼의 키보드 초점 강조는 보존.
3. 합성 예약 입력 → 최종 확인 → 정보 수정 → 재확인 → 가상 요청 완료. 최종 확인 전에는 기록 없음, 완료 후 1건만 기록.
4. WebKit visualViewport.scale이 입력 포커스/완료 단계 전후 일정 범위를 벗어나지 않으며, 예약 결과의 화면 가로 넘침 없음.
5. 별도 키보드 컨텍스트에서 상품 링크 Enter, 예약·검토·완료 제목 초점, 편집/확인 Tab 순서, 완료 후 다음 실제 조작 버튼 초점 강조 확인.
6. JavaScript 런타임 오류 없음. 실제 이름/전화번호·계좌 사용 없음.

## 실행과 한계
- GitHub PR에서 기존 통합 Actions를 실행하고 모두 성공해야만 main 병합 및 Pages 게시 대상으로 판단합니다.
- 실패 시 **검증 결과를 남기고 병합을 보류**합니다. 실제 iOS 문제 해결로 과장하지 않습니다.
- 실제 iPhone Instagram에서 같은 페이지를 다시 방문하여 G3-28/29 화면을 확인하는 수동 테스트가 계속 필요합니다.
- **G2 전체 Gate HOLD 유지**: 실고객 정보, 실제 예약·DB/Auth, 실계좌/은행/송금, 메일·문자·결제·과금·운영 API 연동 금지.
