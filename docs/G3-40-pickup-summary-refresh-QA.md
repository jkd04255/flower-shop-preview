# 오후의 정원 G3-40 · 고객 예약 현황 요약/재확인

## 기준 및 목표
- 출발점: G3-39 최신 `main`. 기존 꽃 사진·모바일 가독성·원본 미니멀 스타일·히어로 문구 `오늘의 꽃 만나기 ↗`, 상품 카드 `상품 상세 보기 ↗` 및 예약/관리자/캘린더 기능 유지.
- 독립 조회 화면 `#/booking-status`에서 고객이 스크롤하기 전에 **픽업 날짜(요일 포함)·시간**을 바로 확인할 수 있도록 예약 카드 제목/상태와 사진 사이에 **2열 정보 띠**를 배치합니다. 기존 상품/픽업/금액 상세정보도 유지합니다.
- 검색 결과가 있을 때만 `현황 다시 확인 ↻` 버튼을 표시합니다. 버튼은 **현재 브라우저의 합성 예약 기록**을 `restoreDemoBookings()`로 다시 읽고 `renderCustomerStatus()`로 카드만 새로 표시합니다. 이 동작은 어떤 네트워크나 실은행·실결제 API도 호출하지 않으며, 검색 중인 예시 4자리 번호를 URL/로컬 저장소에 남기지 않습니다.
- 조회 결과 없음·잘못된 4자리·다른 예약 조회·관리자 가상 데이터 초기화에서는 새로고침 버튼이 숨겨집니다. 상태 요약 메시지는 접근성 안내(aria-live)를 사용합니다.
- 다른 예약 조회 및 G3-39의 모바일 사진/2열 상세/2×2 단계 UX, 기존 PC 왼쪽 사진+오른쪽 상세 구조 보존. 기존 조건에 따른 입금 전 가상 계좌번호 `000-0000-0000`은 **송금 불가능한 시연 문자열**입니다.

## QA
- 기존 GitHub Actions `g3-17-browser-qa.yml`의 **G3-12~39 Chromium/axe/WebKit 전체 회귀 테스트를 모두 그대로 유지**. 이전 G3-39 푸터 버전 검사는 새 G3-40에서도 G3-39 이상을 인식하도록 조정; 원래 기능 검증은 그대로.
- 신규 `tests/g3-40-pickup-summary-refresh-qa.cjs`: 실제 Chromium + Linux Playwright WebKit 각 엔진에서, (1) 고객 조회 전 새로고침 버튼 비표시, (2) 시연 코드 1002에서 날짜·요일·시간과 기존 가상 계좌·상품 정보 확인, (3) 320/390px에서 제목 아래·꽃 사진 위 요약 띠 및 17px 이상 주요 텍스트, 가로 넘침 0, (4) 현황 다시 확인 시 현재 합성 예약·localStorage 변조/네트워크 없이 기존 상태·코드 보호, (5) 키보드 포커스·Enter·상태 라이브 안내, (6) G3-39 다른 예약 조회·확정 샘플 1003·잘못된 4자리·없는 예약번호의 버튼 가시성 및 이전 카드 삭제, (7) axe WCAG 2.1 A/AA 위반 0, (8) PC 사진/상세 좌우 배치 보존, 새로고침 후 코드 사라짐, JS 오류 없음. 모바일 320/390px 스크린샷을 `qa-artifacts`에 보관합니다.
- **전체 QA가 통과한 경우에만** PR squash 병합 및 동일 커밋 GitHub Pages 배포 성공 확인.

## 실서비스 보류
- **G2 전체 Gate HOLD**와 실제 고객 예약·입금·실계좌/은행·결제·DB/Auth·문자/메일·운영 API 등 **실서비스 연동 전면 금지** 유지.
- 4자리 예시 조회는 진짜 본인확인이 아니며, 개인정보를 검색·보관하지 않습니다.
- Linux WebKit 자동 테스트는 실제 iPhone Instagram 인앱 브라우저 QA가 아닙니다. **실기기 검증은 미확인**.

## 모바일 수동 확인
1. 예약 현황 링크에서 `1002` 입력. 상태 배지 바로 아래 **픽업 날짜·요일·시간** 확인 후 가상 계좌 안내 확인.
2. `현황 다시 확인 ↻`으로 같은 브라우저의 상태를 확인하고, `다른 예약 조회 ↗`로 이동한 뒤 `1003`으로 예약 확정을 확인.
3. 실제 iPhone Instagram 내장 브라우저에서는 버튼 터치, 화면 스크롤과 글자 크기를 직접 확인해야 합니다(현재 미확인).
