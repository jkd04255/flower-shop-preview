## 구현 사항
1. **변경 내역마다 ‘위치로 이동’ 버튼** — 매장 기본 정보는 해당 입력칸, 메인 사진은 파일 선택, 상품은 최초로 변경된 입력칸/사진/예약 상태/진열 위치, 순서 변경은 해당 상품 편집 필드로 이동합니다. 삭제된 상품은 최근 삭제 건이면 실행 취소, 이전 삭제 건이면 해당 섹션의 상품 추가/목록 제어로 안내합니다. 삭제한 상품의 존재하지 않는 입력칸으로 이동하지 않습니다.
2. 검색으로 숨겨진 상품이면 **관리자 검색 필터를 해제**하며, 상세가 접혀 있으면 자동으로 펼치고 실제 편집 요소에 포커스를 옮깁니다. `focus({preventScroll:true})` + `scrollIntoView`로 세로 긴 목록에서 해당 위치를 표시하고 시각적 초점선을 보강합니다. 고객 iframe의 필터와 상품 상태는 이 이동 때문에 변경되지 않습니다.
3. **긴 변경 내역**은 제한 높이 내에서 자체 스크롤 가능한 이름 있는 영역으로 구성. 키보드로 영역에 진입해 스크롤한 뒤 각 이동 버튼을 조작할 수 있습니다. 모바일에서는 44px 터치 버튼과 320px 가로폭 맞춤을 유지합니다.
4. G3-73의 기본 데이터 대비 항목 집계, 변경 후 원복, 가격 형식 동등성, 메인/상품 사진 데이터 비노출, `textContent` 기반 보안은 유지합니다. 진열 순서·추가/삭제 변화도 기존과 동일한 범위로 비교하며 변경 건수를 늘리지 않습니다.
5. `renderReview` 호출 간 스크롤 위치를 유지해 반복 편집 시 긴 변경 목록이 불필요하게 맨 위로 튀지 않도록 했습니다.
