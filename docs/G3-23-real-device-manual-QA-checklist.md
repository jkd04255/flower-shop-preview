## A. 시작 전 준비 (실기기별 한 장씩 기록)

| 필드 | 실제 수행 시 기록 |
|---|---|
| 기기 | iPhone 모델 / Android 제조사·모델 |
| OS 버전 | iOS 또는 Android 버전 |
| 브라우저·버전 | iPhone Safari / Android Chrome(기기 기본 브라우저 추가 가능) |
| 화면 방향·배율 | 세로/가로, 화면 확대 설정, 화면 크기 |
| 글자 크기 | 기본/확대(설정 상태와 조절값) |
| 보조기술 | VoiceOver / TalkBack 버전과 켜짐 여부 |
| 검사 날짜·담당 | 실제 수행 시 입력 |
| 최종 결과 | 미실행 / 통과 / 실패 / 해당 없음 |

1. **개인정보 안전:** 자신의 이름·연락처·계좌를 입력하지 않습니다. 예시는 "테스트꽃" 및 사이트 예시 연락처처럼 **명백한 합성 값만** 사용합니다. 예시 번호도 문자/전화 전송에 사용하지 않습니다.
2. 브라우저에서 위 URL을 직접 열고 푸터의 `G3-22 STATIC DEMO` 및 **실제 접수·연락·결제 불가** 표시를 확인합니다. 이 페이지는 고객 서비스가 아닙니다.
3. 기존 시연 데이터가 브라우저에 남았다면 푸터 **관리자 데모 살펴보기 → 가상 데이터 초기화**로 합성 샘플을 복원합니다. **이 작업은 현재 브라우저의 가상 기록에 영향을 주므로**, 개인 테스트 환경에서만 수행합니다.
4. 먼저 기본 글자·화면 크기에서 수행한 뒤 시스템 확대, 화면낭독기, 키보드 순으로 진행합니다. 각 단계에서 원래 설정을 기록합니다.
5. 오류를 재현했으면 입력 값에 개인정보가 없는지 확인하고 스크린샷/동영상과 기기 정보, 예상·실제 결과, 여러 번 재현되는지를 기록합니다. 필요한 경우 종료 시 `가상 데이터 초기화`를 누릅니다.

## B. 기기에서 접근성 기능 활성화

### iPhone / Safari

- **VoiceOver:** `설정 → 손쉬운 사용 → VoiceOver → 켬`. 오른쪽/왼쪽 한 손가락 쓸어넘기기로 다음/이전 항목을 듣고, 선택 후 두 번 탭으로 활성화합니다. Safari에서는 로터의 머리말·링크·양식 제어도 사용해 봅니다.
- **텍스트 확대:** `설정 → 손쉬운 사용 → 디스플레이 및 텍스트 크기 → 더 큰 텍스트`에서 가능하면 접근성 크기까지 확대한 뒤 Safari를 확인합니다. iOS 버전에 따라 메뉴명이 조금 다를 수 있고, 웹사이트가 해당 설정을 그대로 반영하지 않을 수도 있습니다. **실제로 글자가 커졌는지 별도 기록**합니다.
- **화면 확대:** `설정 → 손쉬운 사용 → 확대/축소`에서 확대 기능을 켜고 (동작이 익숙하지 않으면 먼저 Apple 설명 참조) 사용합니다. Safari의 페이지 확대 기능이 별도 제공된다면 100%와 확대 상태도 비교합니다. 이는 **시스템 화면 확대와 페이지 reflow가 다른 검사**임을 유의합니다.
- **외장 키보드가 있으면:** Tab·Shift+Tab으로 이동할 때 포커스 테두리와 스크롤 위치를 추가 확인합니다. 연결하지 않았다면 키보드 항목은 `해당 없음`입니다.

공식 참고: [Apple — Safari와 VoiceOver](https://support.apple.com/ko-kr/guide/iphone/iphe4ee74be8/ios), [Apple — 화면 확대/축소](https://support.apple.com/ko-kr/guide/iphone/iph3e2e367e/27/ios/27).

### Android / Chrome

- **TalkBack:** `설정 → 접근성(또는 손쉬운 사용) → TalkBack`에서 켭니다. 다음/이전 항목을 탐색하며 음성으로 **버튼 이름·상태·양식 라벨**을 듣습니다. 메뉴 위치와 제스처는 제조사·OS/TalkBack 버전에 따라 다를 수 있습니다.
- **시스템 글자 및 화면 크기:** `설정 → 접근성 → 디스플레이 크기 및 글꼴 크기`(또는 디스플레이 관련 메뉴)에서 확대 후 Chrome에서 변화가 실제 적용되는지 확인합니다.
- **Chrome 페이지 확대:** `Chrome ⋮ → 설정 → 접근성`에서 기본 확대 또는 확대 옵션을 확인하고, 사이트별 `⋮ → 확대/축소(Zoom)`가 보이면 100% 및 확대 수준에서 비교합니다. **특정 버전에서 메뉴가 안 보이면 미지원/해당 없음으로 기록**하고 임의로 통과 처리하지 않습니다.
- **외장 키보드가 있으면:** Tab·Shift+Tab 이동과 고정 영역에 가린 포커스를 검사합니다.

공식 참고: [Google — Android 접근성](https://support.google.com/accessibility/android/answer/6006564?hl=ko), [Google — TalkBack](https://support.google.com/accessibility/android/answer/6283677?hl=ko), [Google — Android Chrome 확대](https://support.google.com/chrome/answer/96810?co=GENIE.Platform%3DAndroid&hl=en-GB).

## D. 사진 배경 수동 대비 — 숫자 자동 검사와 구분

1. Safari와 Chrome에서 홈 첫 화면을 열고 밝은 장면 위의 흰색 **브랜드명·작은 마이크로카피·제목·본문·‘오늘의 꽃 만나기’ 링크**를 확인합니다. 화면 크기(작은 폰/큰 폰), 세로·가로, 확대 상태를 각각 기록합니다.
2. 사진이 잘리는 위치가 달라져도 **모든 글자 전체가** 식별되는지 관찰합니다. 특히 글자 끝, CTA 주변의 밝은 꽃잎·하이라이트를 보세요.
3. **시각적 판단**은 “읽힘 / 부분적으로 안 읽힘 / 판정 보류”로 기록합니다. 단지 눈으로 읽힌다는 이유만으로 WCAG 대비율 `4.5:1` 또는 `3:1`을 숫자로 충족했다고 적지 않습니다.
4. 수치 평가가 필요하다면 동일 기기의 스크린샷에서 실제 글자색과 합성된 배경색을 위치별로 분석해야 합니다. 이미지 픽셀 안티앨리어싱·투명도·그라데이션 영향 및 측정 한계를 함께 기록합니다.
5. G3-21 실제 Chromium 픽셀 자동 검사 통과는 이미 확인했지만 **모든 사진·실기기 화면의 수동 판정을 대체하지는 않습니다**.

## F. 판정 규칙 · 후속 작업

- **자동 검증 완료(과거):** G3-22 통합 Chromium/CDP 22/22, G3-21 사진 합성 픽셀·reflow, G3-20 axe-core A/AA 자동 위반 0, G3-12~19 전체 회귀 검사는 [GitHub Actions #42474721337](https://github.com/jkd04255/flower-shop-preview/actions/runs/42474721337)에서 성공했습니다.
