# 오후의 정원 G3-34 · 가장 빠른 픽업 날짜와 관리자 목록 정렬

## 최신 기준선과 변경
- 기준선: G3-33 병합된 `main` (48d2d859f63f9be8cc3cbd8c5f55be89fb54c52a).
- **고객 예약:** `가장 빠른 픽업 날짜 선택 ↗` 버튼으로 오늘~14일 범위의 기존 `pickupSlots()`이 제공하는 첫 픽업 가능일만 선택합니다. 시간은 **사용자가 직접 선택**해야 하며, 기존 정원/영업일/준비시간 조건을 바꾸거나 가상 요청을 생성하지 않습니다. 자동 선택 후 현재 날짜를 안내하고, 날짜를 직접 바꾸면 안내를 지웁니다. 가상 예약 화면을 다시 열면 안내가 초기화됩니다. 날짜 입력의 제약(min/max)과 기존 최종 확인도 유지합니다.
- **관리자:** 기존 필터 아래 `목록 정렬` 셀렉트를 추가합니다. 기본값인 `기존 요청순`은 종전과 동일합니다. `픽업 날짜순`은 화면에 표시되는 배열 복사본만 날짜, 시간, ID 오름차순으로 정렬합니다. 원본 `adminRequests`와 저장 순서는 변경하지 않습니다. 기존 상태 필터, 현재 선택 카드, 관리자 캘린더·수동 입금 확인·상태 전환 동작을 그대로 유지합니다. 가상 데이터 초기화 시 기본 정렬로 돌아옵니다.
- 디자인 톤과 사진, 상품/가격, 고정 문구 `오늘의 꽃 만나기 ↗`·`상품 상세 보기 ↗`, G3-30~33 UX 및 3단계 예약 시연은 보존하며 푸터에 `G3-34 STATIC DEMO`만 표시합니다.

## 자동 테스트
- `tests/g3-34-quick-date-admin-sort-qa.cjs`: 실제 Chromium 및 Linux Playwright WebKit 양쪽의 모바일 390px/320px에서 첫 유효 날짜 선택, 시간 미선택, 수동 날짜 변경·이전 시간 초기화, 키보드 Enter 버튼 동작, 기존 가상 예약 최종 확인/저장·G3-33 메모 초기화·개인정보 미저장, 관리자 기본/픽업 날짜순 정렬, 필터·전체보기 복귀와 현재 카드 유지·원본 배열 불변, 데이터 초기화, 모바일 가로 넘침·JS 에러·axe WCAG 2.1 A/AA 자동 위반 0 검사.
- 기존 단일 GitHub Actions의 **G3-12~33 모든 Chromium·axe·WebKit 회귀 테스트 유지**, G3-34만 추가. 전체 성공인 경우에만 PR 병합과 GitHub Pages 배포 확인.
- 이전 G3-33 회귀 테스트 역시 과거 기능은 보존한 채 새로운 푸터 버전(33 이상)을 검사하도록 수정. 검사를 삭제·건너뛰지 않습니다.

## 운영 정책
- **G2 전체 Gate HOLD**. 실예약·실고객·실계좌/은행·DB/Auth·결제/과금·문자/메일·운영 API **연동 금지**. 정적 합성 데모만 유지.
- Playwright Linux WebKit은 **실제 iPhone Safari 또는 Instagram WebView 검증이 아닙니다**. 실기기 검증은 계속 미확인입니다.

## 사용자 모바일 확인
1. 꽃다발 예약 데모에서 '가장 빠른 픽업 날짜 선택 ↗'를 눌러 날짜만 바뀌고 시간을 별도로 선택해야 하는지 확인합니다.
2. 관리자 데모에서 '목록 정렬 → 픽업 날짜순'으로 바꾸고 기존 필터와 '전체 보기'를 사용한 뒤 원래 요청순으로 되돌려 봅니다.
3. 실제 고객 개인정보나 실제 계좌번호·입금은 사용하지 않습니다.
