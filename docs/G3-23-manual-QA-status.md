## 수동 QA 판정 조건

- P0: 예약 폼 접근 불가, 실송금/실예약을 실제로 한 것으로 오인, 입력 오류의 전달 불가, 관리자/달력 핵심 조작 불가 등. 하나라도 실패하면 해당 기기 시나리오의 접근성 승인을 보류합니다.
- P1: 시스템 글자/화면 확대 후 핵심 콘텐츠 또는 조작 버튼 잘림, VoiceOver·TalkBack의 중요한 상태 안내 미발화, 사진 위 주요 CTA 일부 판독 불가.
- P2: 순서·메시지의 사소한 불편, 외장 키보드 등 부가 시나리오.
- 실기기 통과는 기종·OS·브라우저·보조기술·설정·검사 시각이 기록된 **재현 가능한 실행 결과**가 있을 때만 기록합니다. 각 기기는 독립 판정합니다.
- 수동 QA에서 실패가 재현되면 M번호와 스크린샷/음성 메모(합성 정보만), 기대/실제 결과를 받아 기능 브랜치의 최소 수정 → 통합 Chromium·axe-core QA → 보고서 → PR → 승인된 정적 시안 반영 순서로 진행합니다.

## 변경·배포 결정

G3-23은 **QA 문서만 추가하는 기능 보존 업데이트**입니다. 새로운 실기기 실패가 보고되지 않았으므로 정적 사이트 소스를 수정하거나 공개 배포 버전을 올리지 않습니다. QA/개발 기록은 PR로 검토·병합할 수 있지만, 웹사이트의 최신 확인 가능 버전은 여전히 **G3-22 STATIC DEMO**입니다.

다음 단계는 실제 기기에서 체크리스트를 수행한 뒤 **미실행을 실제 결과로 변경**하는 G3-24 수동 QA 결과 분석입니다. 신뢰할 수 있는 현장 테스트 증거 없이 자동화 결과만으로 iPhone/Android 적합성을 선언하지 않습니다.
