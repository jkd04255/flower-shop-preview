# G3-64 · 고객 예약 현황 현재 단계의 시각적 구분

## 디자인 문제
예약 현황 화면에는 요청 접수·송금 표시·예약 확정·수령 완료의 네 진행 단계가 있습니다. 이미 표시되는 `aria-current="step"` 속성으로 현재 단계는 식별되지만, 모바일에서 이전 완료 단계와 현재 단계의 시각적 구분이 부족합니다. 승인된 미니멀 스타일을 유지하면서 현재 상태만 선명하게 구분합니다.

## 구현 범위
- 600px 이하 예약 현황 카드의 `.cs-steps li[aria-current="step"]`에만 은은한 녹색 바탕(`#eaf1e8`), 짙은 녹색 상단 4px 선, 13px 글씨와 적절한 여백을 적용합니다.
- 이미 구현된 현재 단계의 `aria-current="step"`과 `is-done` 계산을 그대로 사용합니다. 단계명, 상태 코드, 진행도, 실제 예약/입금 상태 변경 로직, DOM 생성은 변경하지 않습니다.
- 과거 완료 및 아직 도달하지 않은 단계의 시각적 표시도 유지하며, 601px 이상 레이아웃은 변경하지 않습니다.
- 새로운 버튼, 문구, 카드, 네트워크 요청은 추가하지 않습니다.
- 꽃 사진·4:3 비율, **'오늘의 꽃 만나기 ↗'**, 예약·조회·관리자·캘린더 전 기능 보존.

## 자동화 검증
`tests/g3-64-mobile-booking-current-step-qa.cjs`를 기존 전체 CI에 추가합니다.
- Chromium/Linux WebKit에서 합성 예약 예시 1001~1004: 네 단계명·기존 stage 숫자·단 하나의 `aria-current` 마커·합성 예약 데이터 일치 확인.
- 320·390·440·600·768·1280px: 모바일의 기존 2열/데스크톱 4열 배치, 현재 단계 배경·글씨·상단선, 가로 넘침 및 범위 보존 검사.
- 고객 현황 새로고침과 다른 예약 조회·입력 초기화, localStorage/합성 데이터 불변.
- 390px axe WCAG 2.1 AA 위반 0건, 스크린샷, JavaScript 오류 없음.
- 기존 **전체** Chromium/WebKit/axe 회귀는 삭제·약화하지 않습니다.
