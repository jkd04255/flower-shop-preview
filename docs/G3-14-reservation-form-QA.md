## G3-13 소스 검토 후 확인한 문제

1. **입력 오류 접근성:** `showReservationError()`가 하단 `role=alert` 글자만 갱신하며 어느 입력칸이 잘못되었는지 `aria-invalid`로 표시하거나 초점을 보내지 않음. 모바일·키보드 사용자는 오류 위치로 돌아가기 어려움.
2. **픽업 날짜 변경 시 시간 재선택:** `updatePickupTimes()`가 이전 `select.value`를 새로운 옵션에 같은 시각이 있으면 복원하도록 설계됨. 날짜가 바뀌면 기존 시각을 자동 확정하지 말고 다시 선택하게 해야 함.
3. **성공 화면/가상 송금 후 초점:** 결과를 표시하며 폼을 숨기지만 결과 제목으로 초점을 옮기지 않음. 가상 송금 버튼을 비활성화한 후에도 안내 문구로 초점을 옮기지 않음.
4. **시간 선택이 모두 불가능한 날짜:** 시간 `select`가 `disabled`인 상태에서 제출 시 `rTime`으로 초점을 옮기려는 동작이 발생하지 않도록, 날짜 필드에 오류와 초점을 지정해야 함.

## G3-14 범위 내 수정

- 예약 날짜·시간 입력은 `rTimeHint` 설명과 연결. 오류 시 해당 필드에 `aria-invalid=true` 및 `rError` 연결, 필드로 초점 이동. 수정 시 오류 문구와 접근성 오류 속성 초기화.
- 날짜 `change` 시 이전 시간 선택을 반드시 비우고 새 날짜의 시간을 사용자가 다시 선택하도록 유도. 단, **같은 날짜**에서 다른 브라우저 탭의 가상 예약 정원만 갱신되면 가능한 기존 선택값은 유지하는 기존 G3-12 정책 보존.
- 가능한 픽업 시간이 없는 날짜는 날짜 선택으로 초점을 돌려 수정 안내.
- 예약 결과 `h2`와 가상 입금 상태 문구를 프로그램에서 초점 가능한 표제로 두고, 성공 후 및 가상 송금 표시 후 키보드/스크린리더 맥락 복원.
- 기존 꽃집 포토그래피·상품 가격·계좌 안내 문안·수동 관리자 확정·캘린더·정원 3건·브라우저 가상 기록 500건·고객 실명/번호 미보관 정책 보존.
- G3-13 QA의 모의 DOM에 표준 `removeAttribute()`를 추가하여 기존 회귀 테스트가 G3-14 접근성 로직에도 사용되도록 유지.

## 반복 실행

저장소 루트에서 Node.js만 있으면 아래 명령으로 실행 가능하며 외부 API 키나 `npm install`은 필요하지 않습니다.

```bash
node tests/g3-12-synthetic-qa.cjs
node tests/g3-13-integrated-qa.cjs
node tests/g3-14-form-a11y-qa.cjs
```

세 테스트는 일부 같은 기능을 반복 점검하므로 총 101종의 완전히 독립적인 사례를 뜻하지 않습니다. G3-14 신규 38건에는 픽업 불가 주말, 같은 시간의 다른 날짜 재선택, 필드별 오류 포커스, 가상 송금 상태 안내 포커스와 개인정보 미저장 검사 등이 포함됩니다.
