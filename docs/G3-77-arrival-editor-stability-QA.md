# G3-77 · 최근 입고 0~20건 편집·iPad 가로 분할 안정화

## 확인된 기준
- 2026-11-12 GitHub 최신 main `288bd911dbaa920708169fd22678cba9011b6af7` (G3-76).
- G3-76 GitHub Pages Actions #43179435198: 해당 main SHA의 build, report-build-status, deploy 모두 성공.
- 전체 **G2 Gate HOLD**, 실제 로그인·고객 DB·실예약/결제·서버 사진 업로드·외부 연동 금지 유지.

## 코드에서 확인된 결함
- 기존 `assets/owner-studio.js`의 `renderArrivals()`는 최근 입고 소식을 추가·삭제·초기화할 때마다 모든 카드에 `replaceChildren(...draft.arrivals.map(renderArrival))` 실행.
- 항목이 20개 가까이 증가하면, 변경하지 않은 기존 카드의 입력칸·사진·초점 요소가 분리됐다 새로 생성됨. 특히 iPad Safari의 좌측 독립 스크롤 영역에서 불필요한 스크롤 앵커 변경, 키보드 포커스 손실 및 이미지 재로딩을 유발할 가능성이 있었음. 원인과 수정 범위를 제한함.
- 20건 상한에 도달해 복원이 불가능한 상태에서도 `ownerUndoArrival`이 활성화되어 있었음. 클릭해도 동작하지 않는 무반응 UI였음.

## 최소 변경
1. **`assets/owner-studio.js`만 제품 코드 수정**: 입고 카드 ID를 기준으로 기존 DOM을 재사용. 추가·삭제 시 바뀐 카드만 생성/제거하고 기존 사진·입력칸·키보드 초점을 유지. `reset` 등으로 실제 데이터가 바뀐 경우에만 유지된 카드 필드를 동기화. 이미 같은 사진이면 `src`를 재설정하지 않음.
2. 입고 개수는 `N개 · 최대 20개`로 표시. 20개에 이르러 복원이 불가능한 최근 삭제 취소 버튼은 비활성화하여 무반응을 방지. 1건 삭제하여 19개로 돌아오면 최신 삭제 취소 동작 복원.
3. 고객용 `index.html`, 가상 예약·조회·관리자·캘린더, 꽃 사진, 브랜드/메인 CTA **오늘의 꽃 만나기 ↗**, 데스크톱 가로 분할 및 G3-75/76 iframe 반응형 CSS·고객 미리보기 로직은 변경하지 않음.
