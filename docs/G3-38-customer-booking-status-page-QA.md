# 오후의 정원 G3-38 — 독립된 고객 예약 현황 화면

## 원인 / UX 개선
G3-37의 홈 매장 안내 폼은 뒷자리 4자리 검색 이후 짧은 문장으로 가상 예약번호와 상태만 표시해, 사용자에게 필요한 꽃다발 종류·픽업 날짜·시간·입금 상태/계좌 안내를 보여주지 못했습니다.

G3-38에서는 기존 URL의 정적 홈/예약 페이지를 보존하고, **별도 전체 화면 `#/booking-status`**를 추가합니다. 새 브라우저 팝업을 띄우지 않는 모바일 친화적 화면 전환이며 홈 상단 **예약 조회**, 매장 안내의 기존 조회 폼, 가상 예약 완료 결과 링크를 통해 접근합니다. 상세화면에서 바로 4자리 예시 코드를 입력할 수도 있습니다.

- 큰 상태 배지·카드·단계 진행표시(요청 접수→송금 표시→예약 확정→수령 완료)
- 상품명과 **기존 실제 시안 상품 사진**, 픽업 날짜·시간, 상품 금액·가상 예약번호
- 입금 전: 은행 미등록 / **계좌번호 `000-0000-0000` (실제 계좌가 아닌 송금 불가능한 예시)** / 가상 입금 예정 금액
- 가상 송금 표시 후: **입금 확인 대기**. 아직 예약 확정 전이며 계좌 안내 대신 확인 대기를 표시
- 관리자 가상 입금 확인과 예약 확정 후: **입금 확인 완료·예약 확정**
- 수령 전/수령 완료/거절: 상태를 각각 구분하고 거절 건을 입금 완료로 잘못 표시하지 않음
- 상태는 언제나 기존 `adminRequests`의 `status`와 `paymentState`로 파생되며, 결제·은행·실제 예약을 변경하거나 발생시키지 않음

## 개인정보·보안 가드
- 기존 샘플 1001~1004는 가상 샘플 코드이며 실제 전화번호와 무관합니다.
- 고객이 새 가상 요청을 생성할 때 입력한 예시 전화번호 **마지막 4자리만 JS 탭 메모리 Map에 연결**. 새로고침이나 탭 종료 시 연결 소실, 관리자 가상 데이터 초기화 시 삭제.
- 코드값/실전화번호/고객 이름/메모는 URL, 결과 카드, 로컬스토리지, 서버에 저장하지 않음. 기존 합성 ID·시간·상품·상태는 기존 데모 기록만 사용.
- 뒷자리 4자리 조회는 **실서비스 인증으로 사용할 수 없음**. 실제 도입에는 본인확인과 조회 접근제어, 서버/개인정보 보안 설계, 사용자 동의가 필요하며 현재 전부 미승인.
- 계좌번호 000-0000-0000은 **시각적 위치를 설명하기 위한 가상 문자열**이며 실제 입금 불가. 실제 은행/송금 API, 실제 입금상태 조회 또는 결제 기능은 없음.

## 회귀 QA
- 기존 전체 GitHub Actions **G3-12~37 Chromium/axe/WebKit** 단일 CI 게이트 보존.
- G3-37의 기존 고객 조회 테스트는 결과가 별도 화면으로 이동하도록 변경된 사항만 정확히 반영하며, 기존 에러·샘플·상태·합성 기록·개인정보 미저장 검증은 유지합니다. 하위 푸터의 버전 검사는 G3-37 이상 허용.
- 신규 `tests/g3-38-customer-status-page-qa.cjs`: Chrome/WebKit에서 독립 페이지 직접 진입, 가상 예약 없는 상태, 샘플 입금 전·송금 표시 대기·예약 확정·거절 구별, 카드의 원본 꽃 사진·종류·시간·가격, 가상 계좌번호/실제 송금 금지, 고객 홈 폼→전용 페이지 이동, 새 가상 예약 연결, 관리자 승인 후 카드 갱신, 개인정보 비저장, axe WCAG 2.1 AA 자동 위반 0, 320/390px 넘침 및 JS 오류 0을 확인합니다. **pending/confirmed 양 엔진 스크린샷**을 QA artifact로 저장합니다.
- 전체 CI 성공일 때만 PR squash 병합 및 Pages 배포 성공 확인.

## 금지 및 미검증
**G2 전체 Gate HOLD 유지**. 실제 고객, 실제 계좌/송금·결제, DB/Auth, SMS/메일, 실제 예약, 개인정보 저장·연동 등 운영 서비스 전부 금지.
Linux WebKit 자동화는 실제 **iPhone Instagram 인앱 브라우저 실기기 QA가 아니며 미확인** 상태입니다.

## 사용자 확인
1. 시안 홈 상단의 **예약 조회**를 누르면 새 ‘내 예약 현황’ 전체 화면이 나오는지 확인합니다.
2. 예시 **1002**: 멜로우 선데이·날짜·13:00·입금 전·가상 계좌/금액 카드 확인.
3. 예시 **1001**: 가상 송금 표시 후 확인 대기. **1003**: 입금 확인·예약 확정. **1004**: 거절.
4. 예시 연락처로 가상 요청을 새로 만들었다면 같은 탭에서 상세 현황 링크를 눌러 확인하고, 관리자가 상태를 바꾼 뒤 다시 조회합니다.
