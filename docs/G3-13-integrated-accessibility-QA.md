## G3-12 기준 전체 흐름 검증

`index.html`의 실제 메인 인라인 JavaScript 전체를 모의 DOM과 `localStorage`로 실행하여 합성 고객/예약만 사용했습니다.

1. 꽃다발 3+2종 노출 → 로지 모먼트 선택.
2. 가상 픽업 날짜·가능 시간 선택 → 샘플 고객 이름과 예시 전화번호로 예약 요청.
3. 가상 요청 기록이 추가되고 고객 이름·전화번호가 브라우저 보존 데이터에서 제외되는지 검사.
4. '가상 송금 완료' 표시 → 관리자 요청 목록 확인.
5. 입금 확인 체크 전 확정 불가, 체크 후 확정 가능.
6. 수동 확정 → 수령 전 → 수령 완료 전환.
7. 해당 날짜 캘린더에 가상 고객/상품과 변경된 최종 상태 표시.
8. `localStorage` 저장·재복원 후 최종 상태 유지.

G3-12 기준 전체 코드 통합 모의 실행 21개 항목 통과. 새 G3-13 테스트는 초점 검증을 포함해 **32개 항목 통과**.

## 확인된 접근성 오류 및 최소 수정

G3-12에서 `renderAdminDemo()`가 가상 예약 목록과 상세 버튼을 `replaceChildren()`로 다시 생성합니다. 같은 `renderCalendarDay()`도 시간대별 `details` 및 상태 변경 버튼을 매번 다시 생성합니다. 따라서 다음 이벤트에서 눌렀던 DOM 노드가 제거되며 키보드 초점이 유지되지 않습니다.

- 관리자 예약 목록 카드를 선택한 후 교체된 동일 예약 카드로 초점 복원.
- 관리자 확정·거절·수령 상태 변경 후 사용 가능한 다음 동작 버튼 또는 해당 상세 제목으로 초점 복원.
- 일간 달력의 수령 전·완료 변경 후 해당 가상 예약의 새 `summary`로 초점 복원.
- 기존 G3-11 체크박스 초점 복원, 월↔일간 날짜 이동, 모바일 반응형 CSS와 상품 디자인은 그대로 유지.

각 예약과 타임라인에 합성 예약 ID를 `dataset.requestId`로 연결하고, 화면을 다시 만든 후 대응 요소로 초점을 복원했습니다. 새 DB/외부 API/실데이터/새 화면은 추가하지 않았습니다.
