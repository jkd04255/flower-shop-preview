# 오후의 정원 G3-42 — Safari 초기 스크롤 끊김 방지

## 사용자가 발견한 문제
G3-41 이후 iPhone Safari에서 홈 진입 직후, 메인 문구가 등장하기 전에 손가락으로 아래로 스크롤하면 콘텐츠가 순간적으로 끊기듯 이동합니다. 새로고침 후 맨 위부터 시작하는 기능 자체는 정상입니다.

## 확인된 코드상 원인
- `hero-peek-v11-script`은 사용자 스크롤을 감지하면 `hero-peek-visible` 클래스를 **즉시** 추가합니다.
- 이 클래스는 `#home>.hero` 높이를 `clamp(108px,14svh,156px)` 만큼 줄입니다. `hero-peek-immediate`로 transition까지 제거되므로 화면 아래 요소가 갑자기 위로 이동하는 레이아웃 점프를 일으킬 수 있습니다.
- G3-41의 홈 reload 스크롤 복원은 `DOMContentLoaded`, `load`, `pageshow`, 두 프레임 이후, 약 180ms에 호출됩니다. 빠른 사용자 제스처가 그 사이 발생하면 이후의 맨 위 이동과 충돌할 가능성이 있습니다.

## G3-42 변경
- 스크롤·터치·휠·키보드 스크롤·메인 내부 앵커 클릭이 **텍스트 등장 전 또는 idle peek 시작 전** 발생하면 예정된 peek를 취소합니다. 초기 히어로 높이를 유지하여 스크롤 중 레이아웃을 재배치하지 않습니다.
- 사용자가 아무 동작도 하지 않으면 기존과 동일하게 첫 문구 1초, 둘째 문구 2초, 이후 약 4.6초에 자연스럽게 아래 섹션이 엿보이는 연출을 유지합니다.
- `prefers-reduced-motion: reduce`에서는 갑작스러운 높이 변경 없이 문구를 바로 보여줍니다.
- G3-41의 실제 홈 새로고침 직후 맨 위 복원은 유지하되, 사용자가 터치·휠·포인터·스크롤 키 입력을 시작한 다음에는 지연 복원 콜백이 화면을 강제로 이동시키지 않게 합니다.
- 일반 홈 링크와 `오늘의 꽃 만나기 ↗`의 기존 섹션 이동, `#/flower/...`, `#/reserve/...`, 예약 조회·관리자·캘린더 데모 라우팅은 그대로 유지합니다.

## 검증 기준
- 기존 `G3-12~G3-41` 합성 QA / Chromium / axe / Linux WebKit 회귀 게이트 유지.
- `tests/g3-42-safari-early-scroll-qa.cjs`를 CI에 추가:
  1. 초기 문구가 뜨기 전에 터치·스크롤 시 hero 높이 유지, 4.6초 이후에도 임의로 접히지 않음.
  2. 스크롤을 하지 않은 방문자는 기존 자동 peek를 정상적으로 봄.
  3. 홈 reload 직후 사용자가 스크롤하면 약 180ms 지연 reset보다 사용자 조작을 우선함.
  4. 메인 CTA 이동과 등장 문구 보존.
  5. reduced motion, 브라우저 JS 오류 검사.
- 테스트 엔진은 Playwright Chromium 및 **Linux WebKit**입니다. 실제 iPhone Safari 또는 iPhone Instagram 인앱 브라우저 실기기 검증을 대신할 수 없습니다.

## 변경하지 않는 정책
- 사진, 상품, 예약 플로우, 디자인, 헤더 문구와 **`오늘의 꽃 만나기 ↗`** 보존.
- **G2 전체 Gate HOLD**. 실제 예약·은행·결제·실고객 개인정보 저장·Auth/DB·SMS/메일 등 실서비스 연동 금지.
- 전체 QA가 통과하고 기존 승인 조건을 만족해야만 `main` 병합 및 GitHub Pages 배포 가능.
