# 오후의 정원 G3-24 · 가상 예약 최종 확인 단계 / QA 보고서

- 기준선: G3-22 공개 정적 시안, G3-23 실기기 QA 체크리스트 문서와 기존 승인 정책. GitHub `jkd04255/flower-shop-preview`.
- 요청: **꽃다발 종류·픽업 날짜 및 시간·예약자 이름·전화번호를 다시 확인**한 뒤에만 예약 요청 완료 단계로 이동.
- 구현 범위: 실제 예약·실고객 데이터·은행/송금/문자·메일/결제/과금·DB/Auth 연동이 아닌 **기존 합성 예약 데모**. G2 전체 Gate **HOLD** 유지.

## 사용자가 보게 되는 동작

1. 예약 폼의 입력값 유효성 검사(날짜·시간·이름·예시 연락처)가 기존처럼 통과하면, 예약을 만들지 않고 **예약 정보를 한 번 더 확인해 주세요** 화면을 표시합니다.
2. 검토 화면에는 **꽃다발 종류, 픽업 날짜, 예약 시간, 예약자 이름, 전화번호**를 표시합니다. 날짜는 사용자의 혼동을 줄이기 위해 다섯 번째 정보로 별도 추가했으며 **모든 값은 `textContent`로만 표기**합니다.
3. **정보 수정하기** 버튼: 입력 폼으로 돌아가며 날짜·시간·이름·연락처 값을 유지합니다. 검토용 텍스트는 즉시 지웁니다. 수정 뒤 제출하면 반드시 다시 검토해야 합니다.
4. **확인하고 가상 예약 요청하기** 버튼: 검토 당시 값과 현재 입력값 일치 여부, 날짜·시간/가상 정원·입력 형식을 **한 번 더 확인**하고, 그때에만 기존 `mockNewAdminRequest`를 호출합니다. 저장 한도 초과·시간 만료 시에는 가상 요청을 추가하지 않고 폼의 오류 안내로 돌아갑니다.
5. 생성 후 기존 **가상 예약 요청 결과 → 가상 송금 완료 표시 → 관리자 수동 입금 확인·예약 확정 → 캘린더** 기능이 그대로 작동합니다.
6. 검토 화면을 뒤로 돌리거나 다른 상품/페이지로 이동하거나 최종 확인한 경우, 검토 화면에 표시된 이름·전화번호를 초기화합니다. 최종 확인 뒤 폼도 초기화합니다. **브라우저 localStorage에는 기존처럼 상품 ID/날짜/시간/상태만 기록**하며 이름·전화번호를 영구 저장하지 않습니다.

이 과정의 **‘예약 확인’은 가상 요청의 최종 제출**을 의미하며 실제 매장 예약 확정 또는 고객에게 알림/송금이 이루어졌다는 뜻이 아닙니다. 실제 매장 예약을 처리하려면 별도 G2 Gate 승인이 필요합니다.

## 디자인·접근성

- 기존 크림·그린 편집형 시안을 보존하면서 `#reserveReview` 패널만 추가했습니다. 320px/390px에서 버튼과 텍스트가 가로로 넘치지 않습니다.
- `role=region`, `aria-labelledby=rReviewTitle`, 제목 `tabindex=-1`로 화면 전환 후 초점을 제목에 두고, Tab으로 **수정 / 확인** 순서로 접근할 수 있습니다.
- 두 버튼에 `:focus-visible` 3px 초점 테두리를 지정하고, 액션/설명 텍스트의 명도를 WCAG 자동 검사가 판단 가능한 범위에 맞췄습니다.
- 기존 G3-22 사진·상품·예약 날짜/시간·가상 정원·저장/복원·관리자 필터·달력 등은 수정하지 않았습니다.

## 남은 일과 제한

- 공개 GitHub Pages는 별도 배포 반영 후 **읽기 전용 버전 표시**를 확인합니다. 사용자 합성 고객 정보를 자동으로 공개 서버에 입력해 실예약을 진행하지 않습니다.
- 사용자께서 실제 iPhone Safari에서 예약 최종 확인 화면을 보며 **정보 수정하기 / 확인**을 직접 시험하는 수동 검사는 아직 **미실행**입니다. Chrome 브라우저 자동 검사는 이를 대체하지 못합니다.
- 실제 계좌/실입금 확인/문자·메일 전송·고객 DB/서버 보안·본인확인·과금·실예약 확정은 이 단계에 포함되지 않습니다. G2 전체 Gate **HOLD**.
